# PS/2 auxiliary controller component

The existing `PcatKeyboard` device can be instantiated as `PcatKeyboard(true)` to include a narrow, optional auxiliary mouse. The existing 286 machine constructs the default keyboard-only controller and retains its previous no-auxiliary behavior. The auxiliary option has no x64 machine, guest CPU, interrupt-controller wiring, scheduling or CLI interface yet. A component test is not a guest boot or physical-controller claim.

The model covers the ClasSICK SPEC-0040 startup sequence: controller `AD`, `A7`, `A9`, `A8`, `20`, `AE`, and `D4`-routed mouse `F5`, `FF`, `F6`, `F4`, including auxiliary ACK `FA`, reset BAT `AA`, and ID `00`. Commands execute synchronously. An unsupported mouse command returns `FE`; this is a narrow test model, not a full PS/2 mouse. Mouse status bit 5 marks auxiliary bytes at the output-buffer head, while keyboard and controller responses are not marked. Keyboard and mouse bytes share an ordered 32-byte queue. Separate IRQ1 and IRQ12 edge indicators are available to a future machine; no guest interrupt path uses IRQ12 yet.

After streaming is enabled, `inject_mouse(dx, dy, primary)` queues a complete three-byte standard PS/2 report atomically. Input coordinates use +X right and +Y down; the emitted packet reverses Y to the PS/2 +Y-up convention. Signed per-axis input is limited to −255..255; larger inputs are rejected rather than silently split or saturated. Zero movement always emits a report, allowing a neutral release before a fresh press. Rejected reports leave the queue unchanged. When disabled, not streaming, or full, reports are rejected. If an auxiliary command response cannot be queued, the response is counted in `dropped_aux_replies()` and the modeled streaming state is not changed. The current `write_port` interface itself has no guest-visible error return for a dropped command reply; a future machine must expose or handle that condition.

The native `pcat_mouse` component test exercises the startup sequence, neutral release, held movement, release/movement, maximum and rejected deltas, keyboard/mouse interleaving, IRQ selection, full-queue atomicity and dropped replies. It generates its own inputs. More commands, packet types, timing, error bits, interrupt wiring, cycle-based input scheduling and replay remain future work. The x64 firmware and CPU required to run ClasSICK are also future work.
